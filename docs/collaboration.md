# 多台电脑的 Codex 开发与交接

每台电脑独立运行 Codex，通过 Git 同步代码和工程交接记录。
本流程不依赖远程连接或官方 Handoff，不同步 Codex 侧栏中的完整对话、
个人记忆、凭据或本机依赖，也不是 meshpi 产品的 Transcript 同步功能。

## 记录位置

- `AGENTS.md`：Agent 的执行规则。
- [任务索引](tasks/README.md)：按任务查找交接文件；仅在新增或关闭任务时更新。
- `docs/tasks/<task-id>.md`：一个任务一份文件，保存当前状态及最近交接。
- [设计决策](decisions.md)：长期有效的决定与理由；任务文件引用对应章节。

任务 ID 使用简短英文名称。新任务从任务索引中的模板复制，禁止把占位符
当成已完成记录。历史交接可通过 Git 查看；不要把所有任务写进同一个状态文件。

## 开始或接手

1. 检查 `git status --short --branch`，保留本机未提交内容。
2. 执行 `git fetch origin`，读取目标远端分支的交接文档，并检查本地与远端差异。
3. 在工作区安全且没有分叉时，检出任务分支并执行 `git pull --ff-only`。
   首次检出可用 `git switch --track origin/<branch>`；本地已有分支则直接切换。
   若有未提交改动、分叉或未推送提交，先检查并报告，不自动 stash、重置或覆盖。
4. 阅读 `AGENTS.md`、任务文件及相关决策，核对代码、分支、PR 和验证记录。
   文档与代码不一致时说明差异；旧版本的测试结果不能视为新代码已验证。
5. 根据依赖变化安装依赖，执行与当前工作相关的验证，再继续下一步。

新任务从安全更新后的 main 建立独立功能分支；已有任务沿用任务分支，
不为了同步而切回 main。索引只展示当前分支可见的记录，其他未合并任务
需要到其远端分支或 PR 查看。

## 阶段结束与换电脑

1. 更新任务文件：改动、重要决定、验证命令及环境、失败尝试、下一步、信息缺口。
2. 检查差异及 `git diff --check`，确认没有私人信息，只暂存本任务文件并提交。
3. 推送前再次 fetch 并检查差异；遇到并发更新保留双方工作，不强制推送。
4. 推送任务分支后再次 fetch，核对 HEAD 与远端跟踪分支一致，检查剩余本机改动。
5. 在回复中给出仓库、分支、任务文档、实际交接提交 ID、下一步和同步结果。
   推送失败必须报告未同步内容；不能在提交前就把“同步成功”写进交接文档。

验证提交字段记录实际接受测试的代码版本。交接提交 ID 在推送后回复，
不要求提交在自己的内容里引用自身哈希。突然关机或未推送的改动无法由本流程保证同步。

电脑 A 可说：

> 我要换电脑了，请交接当前任务，更新任务文档，提交推送，并确认远端同步成功。

电脑 B 可说：

> 继续 meshpi-launcher 任务，先同步远端并读取 docs/tasks/meshpi-launcher.md。

## 并发与公开范围

同一任务轮流在一个分支工作；不同任务使用不同分支和任务文件。
同一任务需要并行时拆分子任务、分支和责任范围，通过 PR 整合。
“最近工作设备”只是便于沟通的别名，不是锁，也不保证互斥。

本仓库公开可见。记录仅包含适合公开的工程信息，不保存完整聊天、密钥、
内部研究数据或私人记忆；不复制或同步整个 `~/.codex` 目录。
本流程没有后台同步服务，Agent 应遵守规则，但以实际 Git 同步结果为准。
